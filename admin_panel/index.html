🌆 Multi-City Setup
Step 1 of the multi-city rollout - safe, isolated, doesn't affect what any customer currently sees
Step 1 - Tag Existing Records

Right now, every bag and every user has no "city" field at all - which is exactly why a new city's listings would currently show to every customer everywhere, mixed in with Jagtial. This step tags every existing record as "Jagtial" explicitly. It does not change anything customers currently see - the actual city-based filtering only gets turned on in a later step, once this is confirmed correct.

Safe to run more than once - it only ever touches records that don't already have a city set.

📲 Notify Users of App Update

Most users get app updates automatically in the background with no visible prompt - this exists for the times that's not fast enough, and you want to actively nudge people to update now. Sends to every user who has ever opened the app with notifications enabled.

What Happens Next

Once you've run Step 1 and confirmed the results below look right, the next steps are:

2. Every new vendor application requires selecting a city.

3. The customer app's home feed filters by the customer's own city (GPS default, manual override available).

4. Only once that's tested does the first Korutla vendor go live.
